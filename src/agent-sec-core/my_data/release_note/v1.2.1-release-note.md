# Agent Sec Core v1.2.1 发布说明

> 本 release note 仅针对 agent-sec-core v1.2.1 发行的 RPM 制品（agent-sec-core / agent-sec-plugins / agent-sec-skills），说明 RPM 安装后用户可感知的新能力、行为变化和升级影响。

## 概览

v1.2.1 是一次以修正与补齐为主的版本：安装体验上，主包通过弱依赖带出 plugins 与 skills 子包，`dnf install agent-sec-core` 之后即可直接启用 adapter；凭据保护侧补充了按命令行参数选择脚本类 Agent、拒绝已退休凭据的 Scope、以及网关局部故障不再整体停服；Cedar 侧支持以 Cedar 作为权限输入并下发 `file.read` 读拒绝；同时修正了 PII 紧邻中日韩文字时的漏检，以及 `scan-prompt` 空输入被误判为通过的问题。

## 新增与增强能力

### 安装即带齐 adapter 资源

`agent-sec-core` 主包以 `Recommends` 方式声明 `agent-sec-plugins` 与 `agent-sec-skills`（精确到 `%{version}-%{release}`）。在默认启用弱依赖的 dnf 环境中，安装主包会一并装上 Cosh/OpenClaw 插件与策略编写 skill，`anolisa adapter enable sec-core cosh|openclaw` 不再因资源目录缺失而失败。仍需要只装运行时的场景，可用 `--setopt=install_weak_deps=False` 或 `--exclude` 保持旧行为。

相关变更：[#9766](https://github.com/agentic-os-org/ANOLISA/pull/9766)

### 凭据保护：更精确的进程选择与更稳的网关

- `agent-sec-cli scope create` 新增 `--cmdline-arg <path>`，按命令行参数精确匹配进程。对 npm 安装的脚本类 Agent（如 `qodercli`），不再需要把该用户下所有 node 进程一并纳入 Scope。
- 创建 Scope 时若引用了全局已退休的凭据，现在会以冲突拒绝，而不是存成 `ACTIVE` 却永远无法签发 fake；daemon 启动恢复对混合 Scope 仍按容错方式处理。
- 发现或校验某个 Binding 时若子进程退出，只丢弃该 Binding 的钉住与路由并单独重试，不再让整个网关进入 fail-closed；其他 Scope 继续提供替换服务。

相关变更：[#9894](https://github.com/agentic-os-org/ANOLISA/pull/9894)、[#9793](https://github.com/agentic-os-org/ANOLISA/pull/9793)、[#9896](https://github.com/agentic-os-org/ANOLISA/pull/9896)

### Cedar 权限输入与读保护

`--permissions` 除原有 JSON 外，现在也接受原始 Cedar 与既有 Cedar 源信封，`sandbox run` 与 PDP 授权请求可共用同一份输入；文件边界在规范化前采集，拒绝可写祖先别名与显式硬链接文件边界。Cedar 下沉路径新增对精确文件 `file.read` 禁止的支持，可经既有 Scope/Binding 下发读拒绝；不支持的后端会在清理旧目标之前拒绝更新。

相关变更：[#9794](https://github.com/agentic-os-org/ANOLISA/pull/9794)、[#9895](https://github.com/agentic-os-org/ANOLISA/pull/9895)

### 检测与命令行行为修正

- PII 扫描：结构化令牌紧邻中文、日文、韩文时不再漏检，邮箱、API Key、身份证号、AccessKey ID 与 Bearer 标签均在紧邻文本时正常识别与脱敏。([#9867](https://github.com/agentic-os-org/ANOLISA/pull/9867))
- `agent-sec-cli scan-prompt --text ""` 及纯空白输入现在返回用法错误和退出码 1，不再以 0 退出且无任何判定，调用方不会再把"没扫"当成"扫过且通过"。([#9786](https://github.com/agentic-os-org/ANOLISA/pull/9786))
- 受限沙箱以只读根加可写挂载启动时，若存在既有硬链接，会在 helper stderr 输出一条边界提醒；执行决策与写入结果不变。([#9868](https://github.com/agentic-os-org/ANOLISA/pull/9868))

## 升级影响

- 默认 dnf 安装会额外拉入 `agent-sec-plugins`、`agent-sec-skills` 及其依赖（`python3 >= 3.11, < 3.12`、`nodejs >= 18`、`jq`）。不需要这些组件的环境请显式关闭弱依赖或使用 `--exclude`。
- 自建镜像与测试环境若依赖"只装主包"的旧假设，需要显式调整，否则 `adapter enable` 会看到与以往不同的包集合。
- 使用 `--cmdline-arg` 的 Scope 属于新增选择项，既有 `--process-name` / `--executable` 的匹配行为不变；通过解析后的 `.js` 路径或相对路径启动脚本不会命中。
- `file.read` 读拒绝只支持已存在的普通文件，目录树读拒绝不支持；替换或轮转目标文件后需要重新下发。
- 出现 hardlink 提醒属于预期提示，不代表启动失败；如需消除该边界，请调整工作区布局。

## 适用用户

- 通过 RPM 安装 `agent-sec-core` 并使用 Cosh/OpenClaw adapter 的用户。
- 使用凭据安全网关与 Scope 做 Agent 凭据替换、需要覆盖 npm 安装类 CLI 的运维与安全团队。
- 使用 Cedar 策略下发文件保护（含读拒绝）的用户。
- 关注 PII 扫描与提示词扫描判定准确性的用户。
