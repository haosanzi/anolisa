# Agent Sec Core v1.3.1 发布说明

> 本 release note 仅针对 agent-sec-core v1.3.1 发行的 RPM 制品（agent-sec-core / agent-sec-plugins / agent-sec-skills），说明 RPM 安装后用户可感知的新能力、行为变化和升级影响。

## 概览

v1.3.1 在 1.3.0 的 Cedar 策略与沙箱基础上补齐了 Skill 安全评估能力，并加强了 sandbox 的写保护、启动权限推导与策略生成可读性，同时修正了事件摘要、代码扫描与 hook 命令构造中的若干问题。

## 新增与增强能力

### Skill Score：可选的 Skill 安全评估

`agent-sec-cli skillsec score plan/run` 现在可以为一个 Skill 生成评估计划、执行探针、收集证据并给出评分与报告。轻量的计划能力随主包直接安装；需要实际执行探针时，用 `sudo agent-sec-cli skillsec score install-runtime` 安装可选运行时，RPM 已随包提供对应的 versioned recipe，安装过程会校验 recipe、证据与镜像凭据后再启用，升级失败时保留上一份可用的已激活运行时。

评估失败时不再只有一条笼统错误：终端诊断会给出发起操作、错误类别与具体失败的运行时文件；Judge 回复缺少 usage、被截断或校验不通过时会分类上报，并在原有时限与请求预算内重试一次，单次 Judge 请求上限放宽到 600 秒，同时按模型应用不同的输出上限，可用 `remote.judgeMaxTokens` 在部署侧下调。

相关变更：[#9430](https://github.com/agentic-os-org/ANOLISA/pull/9430)、[#10505](https://github.com/agentic-os-org/ANOLISA/pull/10505)、[#10604](https://github.com/agentic-os-org/ANOLISA/pull/10604)

### Sandbox 写保护与启动权限

- `agent-sec-cli sandbox run --landlock off|auto|required` 可从可写挂载推导并安装 ABI 3 的写规则；默认 `off` 不做探测，`auto` 在内核不支持或 LSM 未开启时回退到原有 strict sandbox，`required` 则在无法强制时直接拒绝执行。Cosh 从安装的 `landlock.conf` 读取模式。
- 可写 workspace 内显式声明的只读子树现在会被真正强制：只读 bind 按挂载顺序生效，符号链接与不可表达的挂载目标会在命令启动前报错并指出路径，而不是静默放行。
- Cosh command mode 不再要求手工提供宿主机相关的 runtime preset：PEP 会从 launch spec 推导读权限与进程启动权限；显式传入的 `--runtime-permissions` 仍然作为附加规则参与 PDP 判定。

相关变更：[#10391](https://github.com/agentic-os-org/ANOLISA/pull/10391)、[#10306](https://github.com/agentic-os-org/ANOLISA/pull/10306)、[#10588](https://github.com/agentic-os-org/ANOLISA/pull/10588)、[#9211](https://github.com/agentic-os-org/ANOLISA/pull/9211)

### Cedar 策略生成与目录树读保护

- Cedar `file.read` forbid 支持目录树读保护：翻译器会生成带排除项的递归读目标，目录下新增的文件同样受保护（需要 AgentSight 声明 `directory_tree_read_protection` 能力）。
- 生成的任务策略按需求逐条给出可复核的规则说明，并标注 sandbox 启动与 AgentSight 是否能够共同强制；导出结果同时携带覆盖率与兼容性说明。
- 命令提案可为识别出的 PATH 工具申请按名称限定的 `process.spawn`，当文件目标依赖 shell 变量展开时返回明确的澄清原因，而不是给出不完整的策略。

相关变更：[#10523](https://github.com/agentic-os-org/ANOLISA/pull/10523)、[#10529](https://github.com/agentic-os-org/ANOLISA/pull/10529)、[#10614](https://github.com/agentic-os-org/ANOLISA/pull/10614)

### 修复

- `agent-sec-cli events --summary` 只统计最近一次可用合规扫描之后记录的修复，重复扫描不会再虚高修复计数。([#10229](https://github.com/agentic-os-org/ANOLISA/pull/10229))
- 代码扫描的 `target_regexes` 从主规则匹配位置之后开始搜索，操作符前也出现同名敏感路径时不再漏报。([#10473](https://github.com/agentic-os-org/ANOLISA/pull/10473))

## 升级影响

- 启用 Landlock 前请把 Hook、CLI、daemon 与 helper 一并升级到 v1.3.1；未配置 `landlock.conf` 时保持原有 hook 参数，默认行为不变。
- 显式配置了只读子树或跨越符号链接写授权的 sandbox 策略，升级后可能在启动阶段直接报错；请按报错指出的路径调整策略，避免依赖非规范写根。
- 使用 Cosh command mode 的环境可以移除 `AGENT_SEC_COSH_SANDBOX_RUNTIME_PERMISSIONS`；如仍配置了额外 preset，请复核其中的额外权限。
- 目录树读保护需要 AgentSight 支持对应能力；降级到仅支持精确文件读保护的历史版本前，请先移除目录树读授权。
- 回滚到早于本版本的 ASC 时，请先删除模型配置中的可选字段 `remote.judgeMaxTokens`。

## 适用用户

- 需要为自研 Skill 做安全评估与可复核报告的 Skill 作者与评估平台；
- 在 Linux 上依赖 sandbox 写保护、只读子树或 Landlock 强制的部署方；
- 通过 Cedar 策略管理文件读保护与命令提案、并需要审查生成策略的运维与安全同学。
