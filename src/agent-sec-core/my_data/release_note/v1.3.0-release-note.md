# Agent Sec Core v1.3.0 发布说明

> 本 release note 仅针对 agent-sec-core v1.3.0 发行的 RPM 制品（agent-sec-core / agent-sec-plugins / agent-sec-skills），说明 RPM 安装后用户可感知的新能力、行为变化和升级影响。

## 概览

v1.3.0 把沙箱授权从单一 bwrap 后端扩展为可切换的 Docker 后端，把策略授权收敛到 PAP 单一策略集，并补齐凭据保护与沙箱路径例外的操作入口。本版本包含若干**破坏性变更**：网关默认不再随 daemon 启动、部署侧授权配置被移除、凭据注入改为显式 Cedar 策略、Cosh 沙箱授权改用安装模板，升级前请先读「升级影响」。

## 新增与增强能力

### Docker 沙箱后端

主包新增 `/usr/bin/asc-sandbox-docker-guard`，`agent-sec-cli sandbox run` 支持 `--backend docker --image <镜像>`（另有 `--docker-cli`、`--memory`、`--cpus`、`--pids-limit`）。目标程序运行在只读根文件系统、`cap-drop ALL`、`no-new-privileges`、禁用外部 Unix socket 的容器里，宿主路径只能通过授权 bind mount 出现；容器无法精确表达的权限（允许子树内的 deny、mount 级 noexec、保留路径、未被允许规则覆盖的 cwd）一律以 `Unsupported` 失败退出，不做近似降级。默认后端仍是内置 linux-sandbox，Docker 需显式选择。

相关变更：[#9906](https://github.com/agentic-os-org/ANOLISA/pull/9906)

### 沙箱路径例外（excluded_paths）

deny 规则新增可选 `excluded_paths`：在拒绝某个父目录时把当前会话目录等子目录排除在外，命令可以在被豁免的子目录内读写，父目录枚举、兄弟目录和运行后新建的兄弟目录仍不可访问。权限格式仍为 version 1，不带该字段的规则行为不变。该能力需要 Linux 后端以 tmpfs 遮蔽被拒父目录并挂载子目录，依赖 root 与 `CAP_SYS_ADMIN`。

相关变更：[#10255](https://github.com/agentic-os-org/ANOLISA/pull/10255)

### 策略与意图

- daemon 每次普通启动都从当前 PAP 策略集授权，空集合即 DENY，不再依赖部署文件里的策略白名单。
- `agent-sec-cli intent init` 可在无模型、无网络的情况下把显式 allow/deny 规则编译成通过校验的 Cedar 草稿。
- 新增 `intent propose-command`，让 PreToolUse hook 只凭命令行与 cwd 生成 Cedar 候选（`agent-sec-cli intent propose-command --command ...`）。
- `create` 授权缺失路径时改为映射到已存在父目录的写权限，`mkdir -p a/b && printf x > a/b/new` 这类命令在目录写授权下可直接执行。

相关变更：[#9902](https://github.com/agentic-os-org/ANOLISA/pull/9902)、[#9915](https://github.com/agentic-os-org/ANOLISA/pull/9915)、[#9879](https://github.com/agentic-os-org/ANOLISA/pull/9879)、[#10241](https://github.com/agentic-os-org/ANOLISA/pull/10241)

### 凭据保护

- 新增 `agent-sec-cli inject-credential --builtin github`：一次完成 fake 生成、内置 GitHub Policy 注册和 Scope 指派，返回 fake 文件路径与 CA 信息；不打印凭据，也不会替你启用网关。
- 网关 HTTPS 凭据注入改由显式 Cedar 策略描述（`seccore.system@2`、`network.send`、`HttpEndpoint`），支持显式 header、`auto`、`basic` 与单个 `{fake}` 模板。
- 凭据存储的 `flock` 在 drop 时显式释放，不再因并发的子进程继承了描述符而出现重开失败。

相关变更：[#10184](https://github.com/agentic-os-org/ANOLISA/pull/10184)、[#9836](https://github.com/agentic-os-org/ANOLISA/pull/9836)、[#10273](https://github.com/agentic-os-org/ANOLISA/pull/10273)

### Cosh 沙箱授权

新增 `AGENT_SEC_COSH_SANDBOX_ALL_SHELL=1`，开启后每条已 hook 的 shell 调用都走 PDP 与沙箱链路；`AGENT_SEC_COSH_SANDBOX_PERMISSION_SOURCE=command` 支持按原始命令与 cwd 生成权限请求，配合 `AGENT_SEC_COSH_SANDBOX_RUNTIME_PERMISSIONS` 传入运行时预设。RPM 安装的默认请求模板位于 `/etc/agent-sec/sandbox/permissions.json.template`。全部能力默认关闭。

相关变更：[#9954](https://github.com/agentic-os-org/ANOLISA/pull/9954)、[#9918](https://github.com/agentic-os-org/ANOLISA/pull/9918)

### 检测与运行稳定性

- 大体积 Bash 脚本改用线性起点检测加有界验证，前文出现 `crontab -l` 之类无害近似匹配时不再耗尽正则预算，仍能给出正确 finding 与证据。
- `scan-prompt` 多轮模式收到非对象 JSON 时返回清晰错误，不再抛属性异常。
- 事件日志写入遇到被截断的 JSONL 尾行时先补分隔符，中断记录不会再吞掉下一条事件。
- `agent-sec-cli events --summary` 按最近一次扫描的真实结果报告成功或失败，旧扫描的合规数据标记为历史。
- 重启后按当前 boot ID 过滤恢复实例，上一个 boot 残留的 Binding 进入既有清理流程。

相关变更：[#10107](https://github.com/agentic-os-org/ANOLISA/pull/10107)、[#8800](https://github.com/agentic-os-org/ANOLISA/pull/8800)、[#10202](https://github.com/agentic-os-org/ANOLISA/pull/10202)、[#10108](https://github.com/agentic-os-org/ANOLISA/pull/10108)、[#10191](https://github.com/agentic-os-org/ANOLISA/pull/10191)

## 升级影响

升级到 v1.3.0 前请逐项确认：

- **网关默认不再启动**：`agent-sec-core.service` 的 `ExecStart` 仍是 `agent-sec-daemon serve`，未带 `--enable-gateway`。依赖凭据注入的机器升级后网关不会自动起来，需给服务加 drop-in 补上该参数（或手工以该参数启动 daemon），随后用 `agent-sec-cli gateway enable` 恢复运行时代理。
- **部署授权配置被移除**：`baseline_policy`、`task_policy`、`environment_permissions` 与可配置 TTL 均不再接受，daemon 一律按当前 PAP 策略集授权，决策窗口固定 60 秒。升级前请确认 PAP 中已有需要的策略，空集合等于全部拒绝。
- **凭据注入契约变更**：`gateway key add`、`gateway credentials` 及相关 RPC 已删除，`policy create/update` 的 HTTP 凭据策略需显式 `--schema-revision 2`；`responseRewrite` 由字符串改为布尔值，策略里写 `"buffered"` 会被拒绝；Gateway Binding 载荷升级为 `agent-sec-gateway-binding/v2`，daemon 与网关需同版本升级。
- **策略文件默认格式变更**：`policy create/update --file` 默认按原始 Cedar 解析，仍在传 JSON 封装的脚本需补 `--language json`；`policy default --cedar` 已移除，原样输出即为 Cedar。
- **Cosh 沙箱变量变更**：`AGENT_SEC_COSH_SANDBOX_PERMISSIONS` 已移除，改用安装的 `permissions.json.template`（`%config(noreplace)`，你本地的修改会保留）。
- **`make uninstall` 路径对齐**：只用源码安装的用户，`make uninstall` 现在会一并移除 systemd unit 与五个 adapter payload，配置保留策略不变。RPM 用户由包管理器负责，不受影响。
- 建议升级后验证：`systemctl status agent-sec-core`、`agent-sec-cli events --summary` 显示的最近一次扫描结果、以及沙箱授权链路（含新选的 Docker 后端）是否按预期 fail closed。

## 适用用户

- 使用 RPM 安装 agent-sec-core 并依赖凭据注入网关的用户：必须处理「网关默认不启动」与凭据策略契约变更。
- 需要容器化执行环境的部署方：可使用新 Docker 沙箱后端，但需宿主机 root、`CAP_SYS_ADMIN` 与可信 `dockerd`。
- 使用 Cosh / Agent 框架 hook 做命令级授权，或需要为多个会话目录做权限隔离的用户。
- 只使用扫描与事件能力的用户：本次仅包含检测修正与展示修正，无需额外操作。
