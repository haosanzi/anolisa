# Agent Sec Core v1.1.1 发布说明

> 本 release note 仅针对 agent-sec-core v1.1.1 RPM 制品，说明 RPM 安装后用户可感知的新能力、行为变化和升级影响。

## 概览

v1.1.1 是一次以修复为主的补丁版本，重点是补齐代码扫描的一个绕过缺口、调整 CLI 命令组的对外名称，并修正带特殊字符的 Skill 名称在发布后失真或无法解析的问题。同时移除了一个从未被下游支持的 CLI 选项，升级前需要检查脚本。

## 新增与增强能力

### Python 进程内执行的命令纳入 Shell 规则扫描

此前 V2 会把内联 `python -c` 的负载重写为 Python 后再做规则评估，但通过 `os.system`、`os.popen`、`subprocess` 传入的命令字符串从未进入 Shell 规则。这意味着 `rm -rf` 这类破坏性命令写在 Python 里可以返回 `pass`。

安装本版本后，`agent-sec-cli scan-code` 会抽取受支持 Python 进程 API 中直接的、未转义的命令字符串，逐条按既有 Bash 规则评估，并保留原生规则 ID、描述、严重级别和证据（`language` 仍为 `python`）。注释、普通字符串、动态拼接、前缀表达式和 argv 数组不参与推断，行为与之前一致。

相关变更：[#9128](https://github.com/agentic-os-org/ANOLISA/pull/9128)

### CLI 命令组更名为 `skillsec`

`agent-sec-cli` 的 SkillSec 模块此前只暴露旧名 `skill-ledger`。本版本把 `skillsec` 注册为主命令组，`skill-ledger` 保留为别名，参数、输出和退出码完全一致，现有脚本与 Agent Hook 调用不需要改动。`--help` 中展示的是新名称。

相关变更：[#8907](https://github.com/agentic-os-org/ANOLISA/pull/8907)

### 带特殊字符的待发布 Skill 名称不再失真

Rust V2 用 JSON 语法给待发布 Skill 占位符加引号，但 JSON 会把 NEL、DEL 和 Unicode 行分隔符等字符原样保留，而 YAML 会折叠或拒绝这些字符。结果是已被接受的目录名在 Host 读取 frontmatter 时可能被改写或解析失败。

本版本对既有引号标量中剩余的 YAML 敏感字符做转义，待发布 Skill 保持原始目录名，复核说明可正常读取；原有 pending 目标仍然隐藏被拒绝的 Skill。签名校验、激活 schema 和发布生命周期均未改变。

相关变更：[#8948](https://github.com/agentic-os-org/ANOLISA/pull/8948)

## 升级影响

- **`scope create --cgroup-id` 已移除**：该选项此前出现在 `--help` 中，但 PAP 和 AgentSight Adapter 从不接受 cgroup 分配。升级后带该选项的调用会在本地直接失败，退出码 2。请改用 `--pid`、`--process-name` 或 `--executable` 指定目标进程，RPC 拒绝行为、Adapter 执行行为和 SQLite schema 未变。
- **CLI 显示名变化**：脚本里写 `skill-ledger` 的继续可用，无需迁移；仅面向 `--help` 输出做解析的场景需要留意。
- **扫描结果可能变多**：使用 Python 进程 API 执行命令的代码，以前返回 `pass` 的位置现在可能报出 Shell 规则命中，需要重新确认既有基线。

## 适用用户

- 通过 RPM 安装 agent-sec-cli 及各类 hook、并在脚本中使用 `scope create` 的用户（必读升级影响第一条）。
- 依赖代码扫描结果做准入判断的用户：Python 场景的判定结果会变化。
- 通过 Host 发布待发布 Skill、且目录名含控制字符或 Unicode 分隔符的用户。
