# Agent Sec Core v1.2.0 发布说明

> 本 release note 仅针对 agent-sec-core v1.2.0 发行的 RPM 制品（agent-sec-core / agent-sec-plugins / agent-sec-skills），说明 RPM 安装后用户可感知的新能力、行为变化和升级影响。

## 概览

v1.2.0 把 AgentSecCore 的能力主线从"只做检测"推进到"检测 + 授权 + 凭据保护"：新增基于 Cedar 的策略编写与下发链路、沙箱调用的策略授权、可选凭据安全网关，并修正了代码扫描、提示词扫描与 PII 扫描中的若干判定问题。多数新能力默认关闭或需要显式配置，升级本身不会直接改变现有部署的运行行为。

## 新增与增强能力

### 凭据安全网关（可选，默认关闭）

`agent-sec-core` 子包新增网关资产与 `agent-sec-gateway.service`。Agent 进程只持有按 Scope 生成的 fake 凭据，网关在既有 Policy/Scope 授权通过后将其替换为真实值，首批覆盖 GitHub REST 与 HTTPS Git 认证。管理员需显式准备 mitmproxy 并开启网关；未开启时行为与升级前一致。真实凭据以 root 私有文件保存，仅做权限隔离，不做静态加密。

相关变更：[#9265](https://github.com/agentic-os-org/ANOLISA/pull/9265)

### Cedar 策略编写与下发

策略创建/更新现在接受 Cedar 源文件，并在保存前按内置 schema 校验；`agent-sec-cli policy default` 可输出一份可直接改造的受限基线策略。结构化文件保护策略（禁止删除、禁止普通写入或其组合）可经既有 Scope/Binding 生命周期下发到 PEP；超出支持子集的表达式会整条拒绝，不会静默降级。

`agent-sec-skills` 子包新增 `policy-authoring` skill，帮助 Agent 把"只读评审""禁止删除""断网"等自然语言诉求转成可通过官方校验的策略，并明确区分无法表达的约束。

相关变更：[#9298](https://github.com/agentic-os-org/ANOLISA/pull/9298)、[#9442](https://github.com/agentic-os-org/ANOLISA/pull/9442)、[#9522](https://github.com/agentic-os-org/ANOLISA/pull/9522)、[#9463](https://github.com/agentic-os-org/ANOLISA/pull/9463)

### 任务策略候选生成

新增 `agent-sec-cli intent propose --task "run the nightly regression suite"`，根据任务描述生成一份待评审的 Cedar 候选策略。该能力经 daemon 的 `intent.propose` 方法提供，需要设置 `ASC_INTENT_ENABLED=true` 才启用；任务文本会发送到兼容 OpenAI 的云端模型（可能产生费用），生成结果不会被自动下发或执行。

相关变更：[#9450](https://github.com/agentic-os-org/ANOLISA/pull/9450)

### 沙箱执行与策略授权

新增 `agent-sec-cli sandbox run --permissions <json> -- <command>`，在显式 OS 权限集下直接执行命令，不需要策略服务。Cosh 沙箱 Hook 可配置为在执行前走 Cedar 授权：审批面板只展示需要确认的资源操作，执行结果按既有 SQLite/JSONL 安全事件记录。未配置权限文件的安装保持原有行为，`sandbox run` 与 Hook 授权互相独立。

相关变更：[#9311](https://github.com/agentic-os-org/ANOLISA/pull/9311)、[#9379](https://github.com/agentic-os-org/ANOLISA/pull/9379)

### 检测能力修正

- 复合 Bash 命令中追加无害解释器调用时，不再丢失外层已有告警。([#9418](https://github.com/agentic-os-org/ANOLISA/pull/9418))
- 提示词扫描 L2 不再被被扫描文本回显的 `Safety:`/`Categories:` 行降级；代码扫描 LLM 模式下 `bypass`、`denied` 等词内片段不再被当作判定，无法确定时按失败关闭处理。([#9446](https://github.com/agentic-os-org/ANOLISA/pull/9446))
- 接近时限的大体量 PII 扫描请求判定更快，span 与脱敏输出保持不变。([#9453](https://github.com/agentic-os-org/ANOLISA/pull/9453))

### OpenClaw 插件自保护

`agent-sec-plugins` 中的 OpenClaw Code Scanner Hook 现在会拦截原生 `plugins disable`/`uninstall` 对 `agent-sec` 的操作，即使在 observe 模式下也生效；其他插件的管理操作不受影响。

相关变更：[#9491](https://github.com/agentic-os-org/ANOLISA/pull/9491)

## 升级影响

- 从拆分 RPM 回滚到旧布局时，`agent-sec-core` 与 `ws-ckpt` 会保留管理员原有的服务启用/停用与运行状态，包括 disabled、inactive 和 masked 策略。([#9472](https://github.com/agentic-os-org/ANOLISA/pull/9472))
- CLI、daemon、sandbox helper 与 Cosh 扩展需一起升级：新客户端可以读取不带展示来源的决策，旧版严格客户端会拒绝非空的 `approval_requirements`。
- 凭据网关、Cedar 策略下发、Cosh 沙箱授权和 `intent propose` 均为显式启用项；升级后不配置即维持原有行为。
- 扫描判定方向整体更严格：含糊或回显式的模型答复会进入失败关闭路径，原本被误判为通过的结果可能改报扫描错误。
- `agent-sec-skills` 新增 `policy-authoring` 目录，使用 skill 安装路径的用户升级后即可加载。

## 适用用户

- 需要通过 RPM 部署 AgentSecCore 运行时、daemon 与 CLI 的环境。
- 需要给 Agent 配置文件/网络授权策略，或用 fake 凭据替代真实凭据的安全团队。
- 使用 OpenClaw Code Scanner Hook 或 Cosh 沙箱 Hook，关注自保护与执行前审批的团队。
